# ClientSettings 2.2.0 — локальные исправления

Окружение проверки: Evolution CE 1.4.37, PHP 8.3.30, MySQL 5.7.44.

Подтверждены две отдельные причины:
1. Пустая вкладка config/tab10.php не содержит settings. Сохранение вызывало
   array_keys(null): TypeError на PHP 8.3. saveTabs теперь принимает пустой список.
2. Кнопка add_field находится внутри строки foreach. При отсутствии настроек нет
   строки и самой кнопки. editor.tpl теперь выводит одну пустую строку-заготовку.
   Поле без имени saveConfiguration пропускает, в конфигурацию оно не записывается.
3. Удаление последней строки теперь очищает её, сохраняя кнопку добавления.
   После удаления обновляются индексы имён полей.

Ранее внесённые пользователем защиты foreach через ?? [] сохранены.
Не менялись ядро, PHP/MySQL, настройки Strict Mode, error_reporting, модульные
записи БД, плагины, Templates, Chunks, TV, ресурсы и CSS/JS сайта.

Проверки: PHP lint; фактический PHP-шаблон редактора и JS с jQuery/Sortable в
headless Edge (добавление, клонирование, удаление последнего поля, новая вкладка).
Через реальные методы модуля в отдельном config_path внутри backups: создание
конфигурации, сохранение и повторное чтение тестового значения system_settings,
изменение значения, удаление поля. Тестовый ключ mt_stage7_test_value удалён.
Авторизованный полный UI менеджера не проверен. Project Lead должен открыть
модуль, создать поле, сохранить значение, повторно открыть и удалить тестовое поле.
Другие типы полей, права ролей, richtext и пользовательские TV отдельно не проверены.

В установленном наборе файлов нет LICENSE и подтверждённого разрешения на
перепубликацию полного дистрибутива. Полный ClientSettings остаётся незатреканным;
для переноса подготовлен только минимальный патч, без конфигураций и секретов.
На хостинге установить ту же законно полученную версию 2.2.0, сохранить резервную
копию, из корня проекта выполнить:

```sh
git apply --check patches/clientsettings-2.2.0-php83.patch
git apply patches/clientsettings-2.2.0-php83.patch
```

Патч основан на локальной версии с пользовательскими защитами ?? []; при отличии
дистрибутива применить три изменения вручную после сравнения. Не применять вслепую.
На других PHP-версиях не проверено. Новые изменения используют только конструкции,
уже присутствующие в установленном модуле (включая ??); полная совместимость всех
типов полей с другими PHP/Evo не заявляется. Commit/push не выполнены.
