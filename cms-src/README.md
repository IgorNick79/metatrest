# MetaTrest: исходники элементов Evolution CMS

Templates и Chunks выполняются из MySQL. Файлы `.tpl` — точные копии записей БД,
без обёрток, BOM и добавленных переводов строк. Изменение файла само по себе не
обновляет CMS. После изменений через менеджер необходимо обновить соответствующую
копию из БД. Скрипт `scripts/sync_shared.py` обслуживает только статические HTML.
Автоматического импорта или экспорта на этом этапе нет.

## Элементы

Templates: 4 — Главная (`home.tpl`), 5 — Проекты, 6 — Услуги.
Chunks: 1 — Header, 3 — Footer; 4 — ProjectCatalogCard, 5 — ProjectHomeCard,
6 — ServiceCatalogCard, 7 — ServiceHomeItem, 8 — ServiceHomePreview.
Списки обслуживает установленный DocLister. Карточки — небольшие самостоятельные
Chunks, без вложенного дробления. Параметры выборок находятся в Templates.

Prepare-сниппет `MetaTrestCardData`, ID 10, содержит:

```php
return include MODX_BASE_PATH . 'assets/snippets/metatrest/prepare-card.php';
```

Это локальная подготовка данных для DocLister: экранирование обычного текста,
необязательные метаданные, произвольное количество фото и тегов, нумерация по
порядку вывода. Исходники DocLister и ядро Evo не изменены.

## Поля карточек

Обычные поля: `pagetitle` — название, `description` — описание (до 255 символов),
`longtitle` — подзаголовок услуги, `menuindex` — порядок, `published` — публикация.
`content` пока является целью WebLink: отдельные детальные страницы не разработаны.
`introtext` не переопределяется и пока не используется.

| TV ID | Имя | Тип | Привязка к Templates | Назначение |
|---:|---|---|---|---|
| 5 | card_image | image | 5, 6 | Основное изображение, общее для каталога и главной |
| 6 | project_gallery | textarea | 5 | Дополнительные фото: один путь на строку |
| 7 | project_location | text | 5 | Местоположение |
| 8 | project_customer | text | 5 | Заказчик, необязательно |
| 9 | project_period | text | 5 | Период реализации; годы на главной извлекаются отсюда |
| 10 | project_tags | textarea | 5 | Виды работ: один тег на строку |

Пути: `/assets/img/file.jpg` или `assets/images/file.jpg`. Внешние URL не используются.
Не вводить HTML в поля карточек. Пустые метаданные и фотографии пропускаются без
случайных изображений. Старые meta_* TV не менялись.

## Ресурсы и редактирование

- Проекты, ID 2: дети 4 — Новая Голландия, 5 — Реконструкция, 6 — Опоры КАД.
- Услуги, ID 3: дети 7 — Металлоконструкции, 8 — Шпунтовые работы, 9 — Монолитные работы.

Для новой карточки создать дочерний ресурс нужного раздела, выбрать Template 5
или 6 и заполнить обычные поля и TV. Пока нет дизайна деталей, использовать тип
WebLink (`reference`), а не отдельную детальную страницу. После сохранения ID N
цель WebLink: `/projects/#project-N` или `/services/#service-N`. Alias должен быть
уникальным на сайте. При текущих настройках ЧПУ дочерние WebLink имеют плоские
адреса, например `/new-holland/`, и перенаправляют в каталог к соответствующему якорю. Опубликовать ресурс и обновить кеш CMS штатным способом.
Снятие с публикации и удаление исключают карточку из всех выборок.

Списки каталогов выводят всех опубликованных прямых детей, сортировка:
`menuindex ASC, id ASC`. Главная показывает первые 3 проекта и до 7 услуг из тех же
источников. Footer и мобильный список услуг используют все услуги. ID аккордеона
стабилен и не зависит от порядка; видимая нумерация вычисляется при выводе.

Кнопки деталей в каталогах остаются отключёнными. На главной ссылка услуги ведёт
к её карточке в каталоге. Фильтры проектов не реализованы и помечены как недоступные.
Форма не отправляется. Демонстрационных данных в Git нет; для переноса на другой
стенд понадобятся создание схемы TV/ресурсов и назначение шаблонов.

## Проверка Stage 4

Вывод и изменения данных проверены напрямую через локальную MySQL, включая
добавление, изменение полей/порядка, публикацию, удаление и пустые коллекции.
Тестовые временные записи удалены, шесть демонстрационных карточек сохранены.
Проверка создания через UI менеджера требует авторизованной практической проверки:
на этапе доступна форма входа, но нет авторизованной сессии.
